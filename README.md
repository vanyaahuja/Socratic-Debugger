# Evaluating-Open-Source-Models-for-Student-Competence-Analysis-FOSSEE-

## INTRODUCTION
The use of Large Language Models (LLMs) is increasing rapidly in the education sector. Students nowadays rely more blindly on LLMs like ChatGPT, Gemini, etc. for writing codes than on their teachers, and some researchers suggest that “it may weaken essential cognitive skills, including critical thinking, problem-solving, and creativity, which are crucial for academic and professional success” (Karamuk, 2025). As the direct solutions provided by LLMs can hinder critical thinking of students, LLMs equipped with the technique of Socratic tutoring can, in turn, compel the students to think critically for the same. In Socratic tutoring, the tutor leads the student to the answer by asking a series of targeted, logical questions. LLMs instructing the students rather than assisting can encourage their critical thinking and problem solving abilities. This report details the plan to execute a research to check whether LLMs have the capability to give prompts assessing the students’ competence and encouraging them to arrive at the solution on their own by asking thought-provoking questions. 

## RESEARCH PLAN
This research plan evaluates LLMs for their suitability in Socratic tutoring of Python code debugging. To assess the feasibility of my approach, I performed a comparative analysis between two prominent, open-source, instruction-tuned models specialised in debugging codes, Code Llama and Mistral. My analysis was based on a structured test-suite consisting of five diverse test cases: logical error (incorrect operator), off-by-one-error (index error), mutation error (modifying list while iterating), syntax error (missing punctuation), and also a correct code (control case) to verify that the model isn’t hallucinating a bug. Firstly, I tested simple prompts for evaluation, then switched to few-shot prompting technique to guide the models’ behaviour.

Few shot prompting proved to be more efficient as simple prompts generated vague questions for debugging Python code. A diverse test suite was necessary to check the consistency of the outputs generated by the model. After conducting the experiment using both the LLMs, Code Llama and Mistral, I observed that both of them were able to come up with constructive questions when they spotted logical errors but were found to be inconsistent with edge cases like a correct (error-free) code and a code with syntax error. This proves that the two LLMs are not robust enough as they failed to find the issue in a code with syntactical error and also they hallucinated a bug in a correct code. While both models were successful in some cases, they consistently failed in perceiving the student’s situation and also in orchestrating a different strategy. Hence, resorting to a generic response that hinder students’ critical thinking. I inferred that though Code Llama generated meaningful prompts, Mistral’s prompts were marginally better because it was pinpointing the area of confusion without providing the solutions, while Code Llama asked abstract questions that could overwhelm beginners.

## REASONING
1) What makes a model suitable for high-level competence analysis? <br>
A model is most suitable for high-level competence analysis when it is able to understand the complex commands, identifies thought process and, infer meanings from the student’s code, handles unexpected inputs without breaking the persona that is, not simply giving away the answer instead asking appropriate follow-up questions.
2) How would you test whether a model generates meaningful prompts?<br>
I would develop a rubric which will evaluate the generated prompts on the basis of the Relevance to the code, Socratic Quality and Clarity. I would test the model against a variety of test cases which includes codes with logical error, syntax error, off-by-one error and a correct code. The model will generate meaningful prompts if it is not providing the solution directly and in return asks a conceptual question hinting to the mistake.
3) What trade-offs might exist between accuracy, interpretability, and cost? <br>
Accuracy vs Cost: Larger models will generate more accurate prompts but it will require high computational costs whereas smaller and cheaper models are fast but will lack in accuracy and reasoning power. <br>
Interpretability: It is impossible to know the exact reason behind the failure of Code Llama and Mistral on syntax errors and correct code. This lack of interpretability makes the process of fixing the model’s flaws using trial-and-error. 
4) Why did you choose the model you evaluated, and what are its strengths or limitations? <br>
I chose Code Llama and Mistral because they are specialised, open-source models designed for generating human-like text which follows complex instructions in a conversational format. This feature makes them ideal for being a Socratic tutor that needs to ask nuanced and open-ended questions. 

## CONCLUSION
In conclusion, LLMs show potential to act as a Socratic Tutor but they require fine-tuning on real-world teacher prompts to mimic constructive questioning. Also, training must be carried out such that it can accurately differentiate between a faulty and a correct code.
